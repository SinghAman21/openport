# Working conventions for agents

Instructions for any AI agent working in this repository. Architecture rules
and the definition of done live in [CLAUDE.md](CLAUDE.md); this file covers how
to work, not what to build.

## Commits

- **Never add yourself as a co-author.** No `Co-Authored-By` trailer naming an
  assistant, model, or tool. No "Generated with", no "🤖", no attribution
  footer of any kind. The commit is the repository owner's work.
- **Never invent an identity.** Use the git identity already configured
  (`git config user.name` / `user.email`). Do not construct an author from a
  session context, an email seen in a prompt, or a guess at the owner's name.
  If no identity is configured, stop and ask rather than picking one.
- Write the message about the change: what it does, why it is shaped that way,
  and anything a reviewer would otherwise have to reverse-engineer. Do not
  mention the process that produced it.
- Commit only when asked. If asked to commit, do not push unless that was
  asked too.

## Pull requests and issues

The same rules apply to PR descriptions, issue comments, and any other text
that lands in the project's history or its tracker: no tool attribution, no
"generated by" footers.

## Reporting

Report outcomes as they are. If tests fail, say so and show the output. If a
step was skipped or a claim is unverified, say which. Do not describe work as
complete until its acceptance criteria actually pass.
